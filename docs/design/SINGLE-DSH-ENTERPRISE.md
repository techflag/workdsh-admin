# 单 ECS 企业部署

当前开发目标为一个成员服务器容器、按已认证账号固定启动一份官方DSH原生进程，Java管理后台独立。一个账号的多个连接复用该进程；不同账号使用不同身份、Linux UID、Profile和文件空间。不是共享可变身份Host，也不按账号新增常驻容器。

唯一运行源码与构建入口在WorkDSH主仓库deploy/member-process。管理后台只负责账号、组织、服务端授权数据、会话审计与内部模型API，以及该入口复用的登录/账户存储隔离资产。身份来自/auth/me与现行成员登录，不采用专属Runtime grant或启动票据。每个业务读取/写入检查实际成员和组织，服务间key不下发浏览器。

官方Loader/Profile/Session/模型/Remote执行继续由锁定官方DSH负责。自有部署层只承担账号授权、进程生命周期和Linux文件/网络执行边界；不修改官方，不新增Agent loop。共同官方Web与功能包从同一来源导出，企业外置插件显式安装，个人默认组合不被改变。

管理员配置SpringAI多接口公司模型网关。成员在官方自定义模型API手动填写实际内部URL、内部Key、协议与模型ID，不自动注入企业模型。源码、单元测试或本机HTTP入口不能替代目标ECS、完整Linux隔离、真实模型与备份恢复验收。
